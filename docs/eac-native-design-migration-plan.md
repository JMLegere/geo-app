# EAC 1.4.0 Native Design Migration Plan

Date: 2026-05-26

## Goal

Move EarthNova from repo-local Dart-only design registry/tests toward EAC/native SuperBDD design contracts, while preserving the existing Flutter design-system discipline and avoiding a big-bang rewrite.

Target operating model:

```text
product/*.capability / product/*.action / features/*.feature
  -> product/design/**/*.atom|molecule|organism|template|page
  -> artifacts/eac/ui-actions.json generated by a Flutter/Dart collector
  -> mise exec -- eac check
```

EAC core stays language-agnostic. Flutter/Dart is only an evidence collector for the generic UI-action schema.

## Current repo evidence

- `mise.toml` pins `github:JMLegere/eac = 1.2.1`; migration starts by bumping to `1.4.0`.
- `eac.config.ts` currently enables only `product/superbdd` with `product/manifest.ts` and `features/**/*.feature`.
- Product/action truth currently lives in `product/actions.ts`, `product/capabilities.ts`, `product/features.ts`, and `product/workflows.ts`.
- Reusable design currently lives in `lib/shared/design/` with `foundations`, `primitives`, `composites`, `patterns`, a Dart `registry.dart`, and `surface_inventory.dart`.
- Existing design enforcement is in `test/shared/design/*` and should remain during migration as a safety net.

## Recommended migration shape

Do not replace the Dart design registry first. Add EAC native design contracts beside it, get `eac check` green, then collapse duplicated registry facts only after parity is proven.

Reason: the current Dart tests enforce more Flutter-specific boundaries than EAC 1.4.0 does. EAC 1.4.0 gives us cross-stack contracts and UI-action evidence, but not yet every existing style/import/surface rule.

## Phase 1 — Adopt EAC 1.4.0 and wire native contract paths

1. Bump `mise.toml`:

   ```toml
   "github:JMLegere/eac" = "1.4.0"
   ```

2. Extend `eac.config.ts`:

   ```ts
   export default {
     adapters: ["product/superbdd"],
     waivers: [],
     product: {
       manifest: "product/manifest.ts",
       requireBddForAllActions: true,
       requireUnitForMutations: true,
     },
     cucumber: {
       features: ["features/**/*.feature"],
       enforceFeatureInventory: true,
     },
     design: {
       contracts: [
         "product/design/**/*.atom",
         "product/design/**/*.molecule",
         "product/design/**/*.organism",
         "product/design/**/*.template",
         "product/design/**/*.page",
       ],
     },
     uiActions: {
       evidence: ["artifacts/eac/ui-actions.json"],
     },
   };
   ```

3. Run:

   ```bash
   mise exec -- eac init --collector flutter-dart-static
   ```

4. Keep the generated collector as a starting point only. It currently expects action-bearing widgets to expose `actionId: '<product-action>'`.

## Phase 2 — Translate existing design taxonomy into Atomic Design contracts

Create `product/design/` as the SuperBDD-native design source.

Initial mapping:

| Current EarthNova layer | EAC Atomic layer | Initial contracts |
| --- | --- | --- |
| `lib/shared/design/foundations` | no entity / structural notes only | do not force into atoms yet |
| `primitives` | atoms | `EarthActionButton`, `EarthIcon`, `EarthMetaText`, `EarthNotice`, `EarthTag` |
| `composites` | molecules | `EarthFieldRow`, `EarthPanel`, `EarthStatGrid` |
| `patterns` | organisms/templates only if app-facing | likely defer `DesignLibraryExample` or mark experimental structural/catalog |
| feature screens | pages | start with `Map`, `Town`, `Pack`, `VenueDetail`, `Login` only if needed for action evidence |

Example atom:

```text
Atom: EarthActionButton
Status: canonical
Role: button
Interaction policy: action-required
Exports: lib/shared/design/primitives/action_button.dart
Public API: lib/shared/design.dart

Purpose:
  Canonical command button for player-visible actions with token-backed size, tone, and touch target behavior.
```

Example display atom:

```text
Atom: EarthMetaText
Status: canonical
Role: text
Interaction policy: display
Exports: lib/shared/design/primitives/meta_text.dart
Public API: lib/shared/design.dart

Purpose:
  Compact metadata text for field-note labels, provenance, and screen context.
```

## Phase 3 — Add product-action mapping to action-bearing widgets

Start narrow. Do not try to prove every clickable thing in the app on day one.

1. Add an optional or required `actionId` to `EarthActionButton`.
   - My recommendation: make it required for `EarthActionButton` because its contract is `action-required`.
   - If test fallout is too high, introduce `EarthActionButton.unmapped(...)` only for explicit non-product/debug cases.

2. Update button call sites with IDs from `product/actions.ts`.

3. Run the Dart collector to generate `artifacts/eac/ui-actions.json`.

4. `mise exec -- eac check` should then verify:
   - every evidence `actionId` is a known product action
   - every evidence `component` maps to a known `.atom/.molecule/.organism/.template/.page`
   - display/structural entities are not incorrectly mapped to product actions

## Phase 4 — Customize the Flutter collector for EarthNova conventions

The v1.4.0 collector scaffold is intentionally simple. EarthNova should customize it to:

- scan `lib/**/*.dart`
- detect `EarthActionButton(...)` first, not every Widget constructor
- extract `actionId`, `label`, and source path
- optionally map component aliases if wrappers are added later
- fail CI if an `EarthActionButton` lacks `actionId`, unless an explicit `actionMapping: ActionMapping.none(reason: ...)` convention is added later

Output shape stays generic:

```json
{
  "controls": [
    {
      "component": "EarthActionButton",
      "actionId": "inspect-map-cell",
      "surface": "Map cell detail sheet",
      "role": "button",
      "label": "Inspect cell",
      "source": "lib/features/map/presentation/widgets/cell_detail_sheet.dart"
    }
  ]
}
```

## Phase 5 — Decide what to retire

Keep these existing tests initially:

- `test/shared/design/design_contract_test.dart`
- `test/shared/design/design_component_registry_test.dart`
- `test/shared/design/design_library_widget_test.dart`

Retire or simplify only after EAC covers the equivalent facts:

| Existing enforcement | Keep in Flutter tests? | Move to EAC? |
| --- | --- | --- |
| public import boundary | keep for now | future EAC design boundary rule |
| registry parity | migrate to native contracts after parity | yes |
| raw style escape hatches | keep for now | future EAC rule/collector |
| widget smoke/touch target | keep | no, runtime/widget-specific |
| action mapping | move to EAC | yes, now |

## Phase 6 — Verification gates

For the migration PR/change:

```bash
mise exec -- eac check
mise exec -- flutter test --no-pub test/shared/design
mise exec -- flutter analyze
mise exec -- flutter test
npm run superbdd:cucumber
```

## First implementation slice

Smallest safe slice:

1. Bump EAC to `1.4.0`.
2. Add `design.contracts` and `uiActions.evidence` to `eac.config.ts`.
3. Add native contracts for the 8 current reusable design components.
4. Add/customize the Flutter collector scaffold.
5. Add `actionId` to `EarthActionButton` and update only the call sites that already correspond cleanly to product actions.
6. Keep remaining non-action or unclear buttons out of evidence via explicit documented exceptions until EAC supports exact-control waivers.

## Main risk

The risky part is not Atomic Design naming. It is forcing every existing clickable Flutter control into product-action mapping before the action catalog and widget APIs are ready. Keep the first cut centered on `EarthActionButton` and current reusable design components; defer raw Material buttons and feature-local bespoke controls until the collector and action catalog prove stable.

  - native atom/molecule/organism contracts stay in parity with the Dart `designComponentRegistry`
  - the app-level migrated pages/templates stay contracted
  - every native design contract declares status, role, interaction policy, and purpose
- Made `EarthActionButton.actionId` explicitly required and nullable, so product actions are declared with a known ID and design/catalog/demo/non-product usages are explicitly `null`.
- Added `ProductActionSurface` as a no-visual wrapper for non-button clickables that need EAC product-action evidence.
- Customized `tool/eac_collect_ui_actions.dart` to collect:
  - explicit `EarthActionButton(actionId: ...)`
  - explicit `ProductActionSurface(actionId: ...)`
  - existing observable `playerActionId: PlayerActions.*` evidence
  - `surface`, `evidenceType`, and source `line` metadata
  - deterministic deduped output for `artifacts/eac/ui-actions.json`

Current verification gates passed:

```bash
mise exec -- npm run eac:check
mise exec -- flutter test --no-pub test/shared/design
mise exec -- flutter analyze
mise exec -- flutter test --no-pub
```

Remaining migration direction:

1. Keep using the existing Flutter design tests for import boundaries, style escape-hatch prevention, widget smoke tests, and runtime touch-target behavior.
2. Move additional reusable UI into native `.atom/.molecule/.organism` contracts only when it enters `lib/shared/design/` or becomes a repeated pattern.
3. Add stricter raw-clickable coverage later if the team decides every `GestureDetector` / `InkWell` / Material button must either map to a product action or declare an explicit non-product reason.
4. Defer moving product action/capability truth out of TypeScript until the native design/action evidence path is stable in day-to-day work.

## Hardening slice — 2026-05-26

Follow-up cleanup after the initial production migration:

- CI now has an explicit `EAC` job that runs `mise exec -- npm run eac:check`, so native contracts and UI-action evidence cannot silently drift after local-only verification.
- GitHub workflows use `actions/checkout@v5`, removing the Node 20 deprecation warning seen on the previous runs.
- Source-of-truth policy is now explicit in `AGENTS.md`: native `product/design` contracts are authoritative for design/product-surface entities; Dart registries are Flutter runtime projections protected by parity tests.
- App surface contracts now use product-facing names instead of implementation-only class names:
  - `PrimaryNavigationShell` for `TabShell`
  - `ExplorationMapRoot` for `MapRootScreen`
  - `ExplorationMap` for `MapScreen`
  - `PlayerPack` for `PackScreen`
  - `TownDirectory` for `TownScreen`
  - `VenueDetail` for `NpcVenueDetailScreen`
  - `PlayerSettings` for `SettingsScreen`
  - `TerritoryHierarchyHeader` and `MapCellDetailSheet` for feature-level map molecules
- The collector no longer reports observable player-action evidence as the generic `ProductActionSurface` component. It now reports the product surface entity in `component` and the actual capture mechanism in `controlComponent` (`ObservableInteraction`, `ProductActionSurface`, or `EarthActionButton`).
- Raw-clickable coverage is enforced by `test/shared/design/interactive_control_contract_test.dart`: `GestureDetector`, `InkWell`, and Material button controls must expose action evidence directly, be wrapped in `ProductActionSurface`, or carry an explicit `eac-clickable-owner-logs` / `eac-clickable-ignore` reason.
- `CellDetailSheet` venue navigation now uses `ProductActionSurface(actionId: PlayerActions.openNpcVenueDetail)` and has a native `MapCellDetailSheet` molecule contract.
- Bottom navigation destinations now carry static `PlayerActionId`s and the collector emits `static-navigation-destination` evidence for `open-map`, `open-pack`, `open-town`, and `open-sanctuary`.
