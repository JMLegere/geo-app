# Use a bounded client working set

EarthNova targets p95 at or below 100 milliseconds from Player input to the first meaningful UI update for each named primary interaction. App Readiness will hydrate a bounded, persisted, environment- and Player-scoped Client Working Set, serve interaction reads locally, and continue incremental synchronization in the background; explicit Sign out purges the snapshot, refresh failure may enter a Degraded Session only from an internally consistent snapshot, and cacheless failure blocks with Retry and Sign out. This wins over request-on-navigation fetching and a complete fresh preload because those alternatives are network-bound or unbounded; server-authoritative completion remains separate, and readiness progress ends at client usability rather than full synchronization.
